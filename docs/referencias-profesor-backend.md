## Límites verificables: no copiar por inercia

- **SQL Server, EF Core, migraciones, Argon2id/BCrypt locales, JWT HMAC propio, roles del JWT, estado de revocación en memoria, CloudFormation, SQS, sagas y pagos electrónicos** de los ejemplos no se adoptan; el desplazamiento oficial sigue el alcance AWS de DEC-018 (una EC2 + Compose + Nginx + S3 + IAM + CloudWatch), no la guía. La blacklist `revoked:{jti}` y el rate limit críticos en UTTT-GO requieren Redis y fail-closed; el fallback a memoria documentado por WebAPI no es admisible para seguridad.
- [API_SDD `.semgrep/semgrep.yaml`](https://github.com/edelomeza/API_SDD/blob/main/.semgrep/semgrep.yaml) tiene `rules: []` aunque su README anuncia SAST bloqueante; [WebAPI `ci-cd.yml`](https://github.com/edelomeza/WebAPIDevSecOpsScalling/blob/main/.github/workflows/ci-cd.yml) configura Trivy con `exit-code: '0'` aunque el README hable de bloqueo HIGH/CRITICAL. Un control anunciado no equivale a un gate efectivo.
- [WebAPI `schedule-destroy.yml`](https://github.com/edelomeza/WebAPIDevSecOpsScalling/blob/main/.github/workflows/schedule-destroy.yml) destruye infraestructura AWS por horario. UTTT-GO no adopta destrucción programada ni credenciales estáticas AWS; Terraform `apply` requiere pipeline y aprobación. [WebAPI `mutation-nightly.yml`](https://github.com/edelomeza/WebAPIDevSecOpsScalling/blob/main/.github/workflows/mutation-nightly.yml) y [chaos-nightly](https://github.com/edelomeza/WebAPIDevSecOpsScalling/blob/main/.github/workflows/chaos-nightly.yml) son ejemplos, no controles obligatorios de esta fase.
- Los siete endpoints **ya publicados como candidatos locales** no cambian para parecerse a estas referencias. Registrar diferencias significativas y tramitar una propuesta SDD específica antes de alterar contratos, código o pruebas; los dobles locales no demuestran integraciones reales.

## Relación con CI/CD y decisiones

`specs/cross-cutting/ci-cd-devsecops/{spec,plan,task}.md` propone las puertas transversales para todo el backend, enlazando `TASK-AUTH-031` sin completarla ni reemplazar SDD funcionales. El punto 8 del PDF también exige CI/CD móvil: su equipo debe especificar y acreditar su pipeline propia, coordinando compatibilidad/release con backend. Antes de implementar herramientas o publicar imágenes revisar costo, licencia, mantenimiento, seguridad, permisos y atribución. Cambiar una regla permanente o la nube requiere decisión constitucional del equipo; esta guía no la concede.
